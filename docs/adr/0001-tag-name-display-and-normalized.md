# TagName を表記と正規化の組にする

タグ名を登録時に小文字化すると `TypeScript` のような表記が保存できない。小文字化をやめるだけだと SQLite の一意制約が大小を区別するため `TypeScript` と `typescript` が別タグになる。名前の正本は表記（`display`）とし、同一視用の正規化名（`normalized`）は表記から常に導出して永続化する。

**Status:** accepted

## Considered Options

- **小文字化をやめて `name` の一意だけ残す** — 大小違いが別タグになる。却下。
- **ハッシュを同一性キーにする** — 同一視の規則は別途必要なうえ、URL 照合とデバッグが遠回りになる。却下。
- **NFKC や空白畳み込みまで同一視する** — 全角英数や `™` が意図せず潰れる。正規化は trim・NFC・小文字化に止める。
- **`?tags=` を TagId にする** — 改名でもリンクは生きるが、既存の名前キー URL を捨てる。正規化名を載せて互換を残す。
- **SQL の `lower()` / NOCASE に寄せる** — ASCII しか見ず、JS の `toLowerCase` と一致しない。導出はクライアントとサーバーで同じ純関数ひとつに閉じる。

## Consequences

- Tag の同一性は従来どおり TagId。TagName は `{ display, normalized }` であり、小文字文字列ではない。
- 一意制約は `(user_id, normalized)`。`(user_id, name)` は外す。書き込み時に両方を同時に置き、読み取りでドリフトを直す状態は認めない。
- 重複は正規化名で判定する。新規作成や別タグへの改名で衝突したらエラー。同一タグで正規化名が変わらない表記の修正は許可する。作成時に既存の表記は上書きしない。
- 空と 32 文字制限は表記にかける。画面の選択比較は同じ純関数でその場導出する。
- 既存行は同じ関数を一度通して埋める。Title Case はしない。正しい大文字化はアプリから直す。
- 全角と半角は別名前のまま。名前そのものを変えると `?tags=` は変わる。表記だけ直す分には変わらない。
