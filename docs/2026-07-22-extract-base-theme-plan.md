# パーソナル・インデックス UI/UX・Panda CSS 計画

関連: [#106](https://github.com/koralle/pantry/issues/106)

## 目的

意図的に未スタイルにした現在の状態から、Pantryのインターフェースを作り直す。これは自分専用のブックマーク索引であり、URLを素早く保存し、保存済みの項目を素早く取り出し、無理なくタグ体系を保守できることを目的とする。

この再設計は、削除したスタイルシートの移植ではない。既存のデータモデル、ルート、Server Function、アクセシビリティの意味論は、この計画で明示的に変更するものを除いて維持しつつ、新しい情報アーキテクチャ、視覚言語、操作モデル、Panda CSSの実装境界を定める。

## プロダクトの優先順位

1. **装飾より取り出し。** 検索、現在のコンテキスト、項目タイトル、URL、タグを、周囲のUIより速く走査できるようにする。
2. **中断のない登録。** ブックマーク登録では、URL入力、タイトル取得、手動修正、タグ付与をひとつの明快な流れに収める。
3. **コンテキストを見失わせない。** すべて、ひとつのタグ、絞り込み結果のどれを見ているかを常に把握できるようにする。
4. **保守に専用の居場所を与える。** タグ設定とアカウント設定は、閲覧画面の付随操作ではなく、静かで集中できる画面にする。
5. **デスクトップでは高密度、モバイルでは直接的に。** デスクトップは走査と比較を支援し、モバイルは必要なコンテキストを隠さず一度にひとつの作業へ集中させる。

## 体験の方向性

### 視覚言語: パーソナル・インデックス

装飾的なパントリーのメタファーではなく、落ち着いて高コントラストな個人用リサーチツールとして設計する。

- 主操作、選択状態、キーボードフォーカスには、寒色系のニュートラルな下地、濃い文字色、鮮やかなコバルト系のアクセント1色を使う。具体値は基盤実装時にコントラストを検証した組み合わせから決定し、削除済みの色は入力にしない。
- カードや影より、文字組み、余白、細い区切り線を優先する。カード表示のブックマークや確認ダイアログなど、独立して操作できる単位だけがsurfaceを持つ。
- 件数と日付にはtabular figuresを使えるシステムサンセリフを使う。この再設計のためにWebフォント依存は追加しない。
- 直線的からわずかに丸い角、控えめな操作部品の高さ、正確な余白を使う。グラデーション、グラス表現、装飾イラスト、読書を妨げるモーションは使わない。
- タグ色は二次的な索引手掛かりとして扱う。色で表す状態には、必ずテキストまたは選択状態の表現も加える。

### 情報アーキテクチャとナビゲーション

現在のルートとsearch parameterの契約を、ナビゲーション状態の唯一の情報源として維持する。

| コンテキスト     | デスクトップ体験                                                         | モバイル体験                                              | 既存の契約                              |
| ---------------- | ------------------------------------------------------------------------ | --------------------------------------------------------- | --------------------------------------- |
| インデックス     | 常設ナビゲーションと、メインペインのタグ索引                             | コンパクトなトップバーと全幅のタグ索引                    | `/` かつ `view=entrance`                |
| ライブラリ       | サイドバーで選択範囲を示し、メインペインを検索・結果ワークスペースにする | コンテキストバーで範囲を示し、ナビゲーションはsheetで開く | `/` かつ `view=list`                    |
| ブックマーク詳細 | コンテンツの横または下に操作とメタデータをまとめた閲覧カラム             | コンテンツ後に操作を置く単一の閲覧フロー                  | `/bookmarks/$id`                        |
| 登録 / 編集      | 短く順序付けたフォームを持つ中央の作業台                                 | 主操作へ到達しやすい1カラムの登録フロー                   | `/bookmarks/new`、`/bookmarks/$id/edit` |
| タグ             | 管理用リストと集中した詳細・編集画面                                     | 同じ階層を一度に1カラムで表示                             | `/tags`、タグのサブルート               |
| 設定             | 短いアカウント・セッション画面                                           | 特別なナビゲーションモードを持たない同一内容              | `/settings`                             |

デスクトップでは、アプリケーションシェルを固定幅のインデックスレールとコンテンツペインで構成する。レールにはプロダクト名、ライブラリへの入口、作成操作、タグ索引、優先度の低いタグ管理と設定リンクを置く。モバイルではコンテンツペインを全幅にし、同じ索引を名前の明確なナビゲーション操作からBase UIのsheetで開く。

画面上の用語は、タグを「棚」「箱」ではなく**タグ**と呼ぶ。内部のルート名やコンポーネント名は別途整理するまで残してよいが、利用者向けのコピーは削除したメタファーに依存しない。

## 画面設計

### インデックス

デフォルト画面は装飾的なサマリーではなく、タグのディレクトリとする。

- 短い画面タイトルと、ひとつの登録操作を先頭に置く。
- タグ名、ブックマーク件数、任意の色マーカーで構成する、文字優先のレスポンシブグリッドを表示する。
- 既存のピン留め、最近使った順、件数、名前の並び順を使う。ピン状態は索引の走査を助ける場合を除き、タグ管理画面で主に示す。
- 空状態では、タグが将来の取り出しを整理することを説明し、「タグを作成」と「ブックマークを保存」の2つだけを次の操作として示す。

### ライブラリと検索

ライブラリは、取り出しのためのワークスペースである。

- 現在の範囲を見出しとして示す。例: `すべてのブックマーク`、タグ名、選択中タグを示す `絞り込み結果`。
- 検索を最初の操作に置く。検索は明示的に送信し、クエリ状態をURLに保持する。
- フィルターモード、タグの追加・解除、並び替え、表示切替は二次的な操作列に置く。狭い画面では順序を変えずに折り返せるようにする。
- 既存のテーブル/カードの表示設定を維持する。テーブルは比較向け、カードはタイトル、URL、メモのプレビュー、タグの閲覧向けにする。
- 追加読み込みは結果末尾に残す。次ページを読み込む間も既存結果を消さない。
- タグが空の場合と検索結果がない場合を区別し、それぞれに適した次の操作を示す。

### ブックマーク詳細

詳細は管理フォームではなく、読むためのsurfaceとする。

- タイトルと外部URLを最初に置き、続けてメモ、タグ、日時を表示する。
- 主操作は`編集`ひとつに絞る。削除は視覚上は従属させつつ、破壊的操作であることを明確にする。
- Base UIの確認ダイアログ、そのtitle、description、閉じる操作、フォーカス制御を維持する。
- タグリンクは絞り込み済みのライブラリへ戻す。戻る操作は既存のroute helperが保つ選択タグのコンテキストを維持する。

### 登録と編集

作業台は、情報が得られる順に構成する。

1. URLと任意のタイトル取得。
2. 編集可能なタイトルとメモ。
3. タグ選択とインラインでのタグ作成。
4. 主の保存操作ひとつと、強調を抑えたキャンセル/戻るリンク。

タイトル取得の操作は、失敗後の手動タイトル入力を妨げず、自身のpending状態を伝える。バリデーションは対象フィールドの近くに置き、フォーム先頭にも要約する。保存、タイトル取得、タグ作成が失敗しても入力値を保持する。

### タグ管理

タグ管理は、コンパクトな管理用ワークスペースとする。

- リストでは、名前、ブックマーク件数、ピン状態、色状態、編集操作を優先する。
- 作成操作はリストから可能にし、画面全体を大きなフォームにしない。
- 編集画面では、識別子（名前）、順序/ピン、色を別々のセクションに分ける。
- 色swatchにはラベルと`aria-pressed`を付け、色の解除を明示的な操作にする。
- 現在タグ削除ができないことは維持する。プロダクトが実行できない破壊的操作を示唆しない。

### 設定と認証

- 設定にはアカウント情報と明確なsign out操作を置く。閲覧画面のUIと競合させない。
- サインインは、短いプライバシー指向の説明、メール/パスワード入力、ひとつの送信操作を持つ、コンパクトで注意をそらさないフォームにする。
- `/sign-up` のplaceholderは自己登録を提供しないというアーキテクチャ方針と矛盾する。認証画面の視覚実装より前に、削除またはサインインへのリダイレクトで解消する。プロダクトフローとして設計しない。

## 状態、フィードバック、アクセシビリティ

データを扱うsurfaceは、該当する場合にIdeal、Loading、Empty、Partial、Errorを実装する。

| Surface                      | 必要な振る舞い                                                                                                                |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| インデックスとナビゲーション | Loadingでも想定するナビゲーションの形を保つ。Errorでは再試行を示す。タグなしの状態には明確な次の2操作を置く。                 |
| ライブラリ                   | Loadingは選択中のテーブル/カード形を反映する。検索結果なしとタグが空の場合を区別する。Partialの読み込みはリスト末尾に留める。 |
| 詳細                         | 安定した閲覧用skeleton、明示的なnot found、再試行可能な取得エラーを使う。                                                     |
| フォーム                     | バリデーション、タイトル取得、送信エラー中も入力値を保つ。既存のalert/live regionでエラーを通知する。                         |
| タグ                         | Loading中もリスト構造を保つ。データ層が対応するときは、利用できないタグと失敗したリクエストを区別する。                       |
| ダイアログとsheet            | Base UIのフォーカス制御、ラベル付きtitle/description、閉じる操作、キーボード操作を維持する。                                  |

再設計では、landmark、見出し、リスト、表、definition list、label、fieldset、ネイティブinput type、`aria-pressed`、live region、スクリーンリーダー専用テキストを維持する。すべてのinteractive recipeは、見える `:focus-visible` と、タッチ操作に関係する場合は44px以上の操作領域を持つ。

## Panda CSS アーキテクチャ

### 境界

- `src/routes/__root.tsx` は `src/index.css` だけをimportする。
- `src/index.css` はPandaのlayer宣言と生成スタイルシートのimportを持つが、手書きのselectorは持たない。
- `panda.config.ts` はtoken、breakpoint、condition、keyframe、animation tokenを持つ。アプリケーションのレイアウト規則のカタログにはしない。
- `preflight` は `false` のまま、`globalCss` は使わない。要素をrenderするコンポーネントが、その要素のresetと既定スタイルを所有する。
- `styled-system/` は生成物としてGit管理外に置く。`predev`、`pretypecheck`、`prebuild` で生成APIをimportする前に `panda:codegen` を実行する。

### トークンシステム

最初の本番画面をスタイルする前に、セマンティックtokenを定義する。値はコントラストと小画面での見え方を一度検証して決め、リテラル値を重複させずに利用する。

| グループ       | 初期のセマンティック名                                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 色             | canvas、surface、surface-raised、text、text-muted、border、accent、accent-subtle、accent-contrast、danger、danger-subtle、overlay |
| タイポグラフィ | body、label、title、display、metadata、compact/normal/relaxedのline-height、tabular numeric feature                               |
| 余白           | ページ、section、control、inlineの余白を名前で表す、意図を持った4px基準のスケール                                                 |
| サイズ         | touch target、icon size、input height、desktop rail width、readable content width、compact form width、dialog width               |
| 角丸と罫線     | control、panel、full、hairlineと強調用のborder width                                                                              |
| モーション     | 高速フィードバック、標準transition、skeleton pulse、spinner、コンテンツ入場、reduced motionの上書き                               |
| breakpoint     | 1カラムから2カラムへの切替用の `sm`、常設デスクトップナビゲーション用の `md`                                                      |

カスタムPanda conditionは、選択中タグや押下済みtoggleなど、再利用するセマンティックなstate selectorにだけ追加する。それ以外は、組み込みの `_focusVisible`、`_disabled`、`_hover`、レスポンシブconditionを使う。

### スタイルの所有

| Panda API           | 使う対象                                                                                                    | 使わない対象                         |
| ------------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| `css()`             | コンポーネント固有の静的レイアウト、タイポグラフィ、reset、単発の視覚的詳細                                 | 画面横断のvariant、実行時データ値    |
| `cva()`             | button tone、tag chip mode、選択中ナビゲーション、color swatch、skeleton形状など、単一要素で繰り返すvariant | 汎用Reactコンポーネントの抽象化      |
| `sva()`             | form field、form summary、dialog、sheet、UI stateなど、連携するslot                                         | classがひとつだけの単一要素          |
| Panda pattern       | 単純なstack、row、grid、centeringのレイアウト                                                               | 複雑なshell、table、dialogの幾何構造 |
| CSS custom property | 実行時のタグ色だけ                                                                                          | 静的なtheme値、コンポーネントvariant |

共有スタイル関数は、共有UIの契約の近くに置く。例: `src/components/ui/button.recipe.ts`、`form-field.recipe.ts`、`tag-chip.recipe.ts`、`ui-state.recipe.ts`。機能固有のスタイルは機能コンポーネントの隣に置く。スタイルのためだけに新しいReact wrapperを作らず、既存のセマンティック要素とBase UI slotへrecipe classを適用する。

所有する各要素では、必要な既定値だけをresetする。bodyのmarginは`RootDocument`、heading/paragraph/listのmarginは該当コンテンツ、tableの既定値はtableコンポーネント、ネイティブcontrolの既定値はbutton/form recipeが担当する。広範なreset selectorは導入しない。

## 実施計画

### 1. デザイン基盤

対象: `panda.config.ts`、`src/index.css`、`package.json`、`src/routes/__root.tsx`

1. サインイン、インデックス、ライブラリを代表画面として、パーソナル・インデックスの方向性を確認する。
2. コントラストを検証したtoken値、type scale、spacing scale、control height、breakpointを決めて記録する。
3. Panda token、condition、keyframe、code generationのライフサイクルscriptを追加する。
4. `index.css` から生成スタイルシートをimportし、`RootDocument` のPanda classでbodyの既定値だけを適用する。
5. グローバルresetや手書きselectorを導入していないことを確認する。

### 2. 共有フィードバック・インタラクション部品

対象: `src/components/ui-state.tsx`、`src/components/pantry-motion.tsx`、新規の `src/components/ui/` 配下

1. button、text link、form field、form summary、tag chip、UI state、motion用の、スタイルだけを持つ `cva()` / `sva()` recipeを実装する。
2. これらのrecipeへfocus-visible、disabled、pressed、error、reduced motionの振る舞いを適用する。
3. 既存のloading、empty、error、skeleton、motionコンポーネントを、propsとARIA契約を変えずに移行する。
4. 局所的な重複が大きくなった場合だけ、小さな共有のvisually-hidden style helperを追加する。

### 3. ナビゲーションとインデックス

対象: `src/routes/_protected.tsx`、`src/features/tags/components/shelf-nav.tsx`、`src/features/tags/components/entrance-boxes.tsx`

1. デスクトップレール、モバイルコンテキストバー、Base UIのナビゲーションsheetから成るレスポンシブなアプリケーションシェルを作る。
2. タグ閲覧をパーソナル・インデックスとしてスタイルし、利用者向けの棚/箱のコピーをタグ/インデックスの用語へ置き換える。
3. 選択状態、件数、実行時の色マーカー、loading、empty、retry状態を適用する。
4. コンテンツ画面へ進む前に、キーボードナビゲーションと狭い/広い画面幅のレイアウトを検証する。

### 4. ライブラリと詳細

対象: bookmark list/tableコンポーネント、bookmark detail route

1. URL searchの振る舞いを保ちながら、検索を先頭にしたライブラリヘッダーと二次的なフィルター操作を作る。
2. 保存済みの表示設定、コンポーネント内に閉じたtable/listのreset、安定したloading placeholderを持つテーブル/カード表示を実装する。
3. 選択タグ、検索結果なし、タグが空、partial loading、再試行可能なload more errorを実装する。
4. 読むことを優先した詳細レイアウトと、スタイル済みのBase UI削除dialogを実装する。

### 5. 登録、編集、タグ保守

対象: bookmark workbench、tag selector、タグコンポーネントとroute

1. 順序付けた登録/編集の作業台と、field/form単位のフィードバックを実装する。
2. タグ付与の振る舞いを変えず、インラインタグ作成と選択をスタイルする。
3. タグ管理リスト、quick add、編集section、アクセシブルなcolor palette、pin、sort order操作を実装する。
4. すべてのフォームがpendingと失敗をまたいで入力値を保つことを確認する。

### 6. 認証、設定、ルート整理

対象: sign-in route/form、settings route、`src/routes/sign-up.tsx`

1. 同じform/action recipeを使い、コンパクトなサインインとアカウント/設定画面を実装する。
2. サポートしないsign-up placeholderを削除またはリダイレクトし、プロダクトのアーキテクチャに合わせる。
3. sign outが状態をクリアし、完成したサインイン画面へ戻ることを確認する。

### 7. 旧マークアップの削除と検証

対象: 影響するすべてのTSX

1. コンポーネントを移行するたびに、残っている非機能の `pantry-*` classと `--pantry-*` 参照を削除する。
2. `app.css` と `kiso.css` が再導入されていないことを確認する。
3. デスクトップとモバイルの視覚階層、キーボードナビゲーション、focus、dialog、sheet、色コントラスト、reduced motionをレビューする。
4. 自動検証とブラウザ検証をすべて実行する。

## 検証

UI全体の実装後に次を実行する。

```bash
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

Playwright MCPで、デスクトップ幅とモバイル幅の両方において次のフローを検証する。

1. サインインし、タグインデックスを閲覧し、タグを開き、検索し、タグフィルターを追加/解除し、並び替えと表示を切り替え、さらに結果を読み込む。
2. ブックマークを開き、タグのコンテキストをたどり、編集して保存し、再度開き、確認dialogを通じて削除する。
3. タイトル取得の成功と失敗の後に、インラインタグ作成を含めてブックマークを登録する。
4. pin、色、色の解除、sort orderを含めてタグを作成・編集する。
5. すべてのフローをキーボードで完結し、見えるfocus、alert/live region、reduced motionの振る舞いを確認する。

## 完了条件

- インデックス、ライブラリ、詳細、登録、タグ、設定、認証を通して、一貫したパーソナル・インデックスの体験を提供している。
- すべての視覚スタイルはPanda APIまたは生成tokenで定義され、`index.css` は生成スタイルシートの入口だけを担う。
- すべての要素のreset/既定表現は、その要素をrenderするコンポーネントが所有し、グローバルresetや `globalCss` を使っていない。
- 明示したsign-up整理を除き、既存のデータ振る舞い、URL契約、ネイティブの意味論、Base UIのフォーカス制御、Formischのバリデーション挙動を維持している。
- `pantry-*` class、`--pantry-*` variable、`app.css`、`kiso.css` が残っていない。
- 自動検証と、定義したブラウザ/アクセシビリティフローが成功する。
