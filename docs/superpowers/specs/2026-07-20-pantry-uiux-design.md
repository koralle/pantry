# Pantry UI/UX Design

## Goal

自分専用ブックマークマネージャ Pantry の画面UIを、最低限のマークアップから日常利用に耐える物置体験へ引き上げる。デスクトップとモバイルを同等に本線とし、タグを棚／箱として取り出す導線を最優先する。

関連: タグ列の拡張は [2026-07-20-tag-pantry-fields-design.md](./2026-07-20-tag-pantry-fields-design.md) で先行済み。

## Constraints and Decisions

| 項目       | 決定                                            |
| ---------- | ----------------------------------------------- |
| デバイス   | デスクトップ／モバイル同等（レスポンシブ本線）  |
| コンセプト | 家の物置（Pantry）。タグ＝棚／箱。取り出し優先  |
| 入口習慣   | タグから絞り込む                                |
| 一覧表示   | 行リスト（テーブル）↔ カード切替                |
| 詳細       | 余白多め                                        |
| IA         | 棚ナビ × 玄関の箱グリッドのハイブリッド         |
| 「すべて」 | 棚ナビ先頭に固定。玄関グリッドには置かない      |
| 見た目     | 明るいパントリー棚。くすんだティール1アクセント |

## Architecture: Hybrid Shelves

### Roles

| 面                         | 役割                                                  |
| -------------------------- | ----------------------------------------------------- |
| 玄関（ホーム・タグ未選択） | よく使う箱のグリッド。物置の入口                      |
| 棚ナビ                     | 全タグ＋「すべて」。常時（Desktop）／シート（Mobile） |
| 一覧（棚の中）             | 選択中タグ（群）のブックマーク。テーブル ↔ カード     |
| 詳細                       | 取り出した1点                                         |
| 登録／編集                 | しまう／並べ替える作業台                              |
| タグ管理                   | 箱のラベル・ピン・色などの裏方                        |
| 設定／サインイン           | 鍵と道具。メタファーは弱め                            |

### Tag semantics

- 箱タップは最初の1タグをセットする。
- 2つ目以降のタグは一覧上のフィルターで追加する（AND/OR は現行どおり）。
- 玄関の箱並び: `pinned` 優先 → `last_used_at` 降順 → ブックマーク件数降順 → 名前昇順。
- 棚ナビ並び: 「すべて」→ ピン留め（`sort_order` 昇順）→ 非ピン（`sort_order` 昇順、同値は名前昇順）。
- `last_used_at` 更新: そのタグで一覧を開いた／絞り込みに使ったとき、およびブックマーク登録・編集で付けたとき。リネームや削除だけでは更新しない。
- 「未整理」（タグ0件）は専用テーブルを持たずクエリで導出できる。MVPの棚ナビ必須項目は「すべて」のみ。「未整理」行は後続で追加してよい。

### URL / selection states

中央ペインは次の3状態を URL（search params）で区別する。

| 状態   | 中央             | 例                                        |
| ------ | ---------------- | ----------------------------------------- |
| 玄関   | 箱グリッド       | `view=entrance`（アプリのデフォルト着陆） |
| すべて | 全件一覧         | `view=list` かつタグフィルタなし          |
| 棚の中 | タグ絞り込み一覧 | `view=list` かつ `tags=...`               |

ブランドロゴ「Pantry」は玄関へ戻す。棚ナビの「すべて」は全件一覧へ行く（玄関ではない）。

### Desktop layout

- 左: 棚ナビ（固定幅）。右上: 検索・表示切替・「＋」・設定へのリンク。
- Sign out の主置き場は設定画面。Desktop ヘッダー末尾にコンパクトな出口を置いてもよい。
- 中央: 上記 URL 状態に従う。
- 棚・ヘッダーは View Transition で動かさない。
- テーブル ↔ カードの選択は `localStorage` にバージョン付きキーで保存し、端末ごとに覚える。

### Mobile layout

- 初回／玄関: 箱グリッド全画面＋主要アクション（新規など）。
- 一覧: 全画面。上部に「今いる棚」チップ。「棚を変える」でシート（＝Desktop サイドバー相当）。
- 箱グリッドはおおよそ2列。

## Visual Direction

### Tone

明るいパントリー棚。清潔な下地、細い区画線、ラベルで箱を示す。装飾より区画とコントラストで探す。暗い夜の書斎やクラフト紙の手作り感は採らない。

### Tokens (intent)

| 役割       | 方針                                                          |
| ---------- | ------------------------------------------------------------- |
| 地         | ほぼ白〜ごく薄い暖灰                                          |
| 文字       | 濃い墨〜チャコール                                            |
| 区画線     | 細い中間グレー                                                |
| アクセント | くすんだティール1色（選択中の棚、主CTA、フォーカス）          |
| 箱の色     | `tags.color` があれば小さな色帯／ドット。なければニュートラル |
| 影         | ほぼ使わない。階層は線と余白                                  |

避ける: 紫グラデ、クリーム＋テラコッタ、新聞紙レイアウト、グロー、過剰なピル／多重シャドウ。

### Typography

- ブランド「Pantry」: やや幅のあるサンセリフ（銘板感）。ナビで存在感を持たせるがヒーロー級に拡大しすぎない。
- 棚名・箱ラベル: 短く太め、スキャンしやすい。
- 一覧タイトル: 可読本文サイズ。カード時は少し余裕。
- UIラベル: 和欧混植で崩れにくいサンセリフに統一。
- 具体フォントは実装時に見出し用＋本文用の最大2候補まで絞る。

### Component appearance

- 玄関の箱: 角は少しだけ丸める。上端の細い色帯または左ドット、名前、件数。カード乱用はしない。
- 棚ナビ: リスト。選択中は左ティールバーまたはごく薄い背景ハイライト。
- テーブル: 薄い罫線。タグは小さなラベル（塗りつぶしピルの山は避ける）。
- カード: 余白多め。タイトル主、URL副、メモ最大2行。
- 詳細: 広い余白。タイトル大きく、URL／メモ／タグが縦に呼吸する。
- フォーム: 1カラム、ラベル上付き、主ボタンはアクセント1つ。

### Motion

1. 玄関→一覧: 軽いフェード＋わずかな上方向（箱を開ける）。
2. 棚どうし: 中身だけクロスフェード（ナビは静止）。
3. テーブル↔カード: 短いクロスフェード。派手な並べ替えはしない。
4. 一覧→詳細: 階層感のある forward（実装時に View Transition 方針に合わせる）。

`prefers-reduced-motion` ではすべて即時切替。

## Screen Details

### Sign-in `/sign-in`

- 中央1カラム。上に Pantry、短い一文（例: 「自分の棚に入る」）。
- メール／パスワード、主ボタン1つ。エラーはフィールド下＋要約。
- 装飾は最小。

### Entrance (home, no tag selected) `/`

- よく使う箱グリッド（ピン → `last_used_at` → 件数）。
- 「すべて」はグリッドに出さない。
- 空状態: 箱がない旨＋タグ作成／新規ブックマーク導線。

### List (inside a shelf) `/` with search params

- 上部: 今いる棚名、検索、AND/OR、ソート、テーブル↔カード切替。
- 複数タグはチップで追加／削除。
- テーブル: タイトル・URL短縮・タグ・日付。行で詳細へ。
- カード: タイトル主、URL副、メモ2行、タグ。タップで詳細。
- 「さらに読み込む」は末尾。0件時はフィルター解除の提案。

### Bookmark detail `/bookmarks/$id`

- 余白多め。タイトル、外部リンクURL、メモ、タグ、作成／更新（JST）。
- 編集・削除（確認付き）。「一覧へ」は現在の棚コンテキストを維持。

### Bookmark new / edit

- 1カラム作業台。URL → タイトル取得 → タイトル・メモ・タグ。
- タグは候補＋インライン新規。選択中は箱ラベル風。
- 保存が主CTA、キャンセルはテキストリンク。

### Tags `/tags` and tag new / edit / detail

- タグ一覧は裏方の棚管理。ピン／並び／色の編集入口（実装は段階可）。
- 行: 色・名前・件数・ピン。タップの推奨先はその棚の一覧。
- 新規／編集: 名前必須、色はパレット、ピンはトグル。
- 詳細: 紐づくブックマークへの導線を主にする。

### Settings `/settings`

- アカウント表示、Sign out。物置装飾はほぼなし。
- MVPで機能が少なくても、余白のあるシンプルリストとする。

## Five UI States

すべてのデータ表示面は次の5状態を設計する。Empty と Error を混ぜない。

| 状態    | 意味                     | 原則                                                           |
| ------- | ------------------------ | -------------------------------------------------------------- |
| Ideal   | 想定どおり中身がある     | § Screen Details の本線                                        |
| Empty   | まだ／条件に合うものが0  | 次の一手を1つ示す。責める文言は使わない                        |
| Loading | 取得中                   | レイアウトを先に出し、最終形に近いスケルトン。跳ねない         |
| Partial | 一部だけある／続きがある | それまで見えていたものを消さない                               |
| Error   | 失敗                     | 領域内で再試行。フォームは入力を消さない。短いテキストも付ける |

### Per-surface mapping

**Entrance**

- Ideal: ピン／よく使う箱。
- Empty: 箱なし＋作成導線。
- Loading: 2列グリッド形のスケルトン。
- Partial: 段階表示が難しい場合は全体 Loading でよい。
- Error: グリッド領域に再試行。

**List**

- Ideal: テーブルまたはカード。
- Empty: 棚が空／検索0件で文言を分ける。
- Loading: 表示モードに合わせた行／カードスケルトン。
- Partial: 先頭ページ＋「さらに読み込む」。追加読込中は末尾だけ進捗（一覧は残す）。
- Error: 初回失敗は領域エラー。追加読込失敗は末尾メッセージ＋再試行（既存行は残す）。

**Detail**

- Ideal: 余白多めの1件。
- Empty: 見つからない（削除済み等）→ 一覧へ。
- Loading: タイトル／本文ブロックのスケルトン。
- Partial: 使わない（1件取得が単位）。
- Error: 再試行または一覧へ。

**New / Edit**

- Ideal: 入力可能。
- Empty: 初期空フォーム（正常）。
- Loading: タイトル取得中は該当操作を disabled＋短い進捗。保存中は二重送信防止。
- Partial: タイトル取得失敗でも URL・手入力タイトルで続行できる。
- Error: フィールド下／フォーム上部。入力値は保持。

**Shelf nav / Tags**

- Ideal / Empty / Loading（短いリストスケルトン）/ Error。
- Partial: 件数の後付けは可。件数なしでも箱は押せる。

**Sign-in**

- Ideal: フォーム。Loading: 送信中。Error: 認証失敗。Empty / Partial はほぼ該当なし。

### Accessibility (with states)

- 箱・行・カードはキーボードで到達・活性化できる。
- 表示切替・AND/OR・ピンは選択／押下状態が伝わる（例: `aria-pressed`）。
- フォーカスリングはアクセント色で常に見える。
- 色だけに依存しない（箱の色＋名前）。
- タッチターゲットは目安 44px 以上。
- エラーは `aria-live` またはフォーカス移動で通知。
- ダイアログのフォーカストラップは標準パターンに任せる。高度な announcement の作り込みは当面やらない。

## Out of Scope

- ブラウザ拡張からの直接登録
- OAuth / パスキー / アカウント自己管理の拡充
- タグ階層、タグマージ、URL canonicalization
- ブックマークの favicon / OG 画像保存
- 独立HTTP API
- 本仕様の見た目トークンの厳密なデザインシステム化（実装時にCSS変数へ落とす）

## Implementation Notes

- データ列（`pinned` / `sort_order` / `color` / `last_used_at`）は既存マイグレーション済み。本仕様の実装では更新API・一覧ソート・玄関クエリ・UIを載せる。
- 検索・タグ絞り込み・ソートの Server Function が未完成なら、一覧UIより先または同時に揃える。
- 実装は画面単位で段階分割してよい。推奨順: 共通シェル＋棚ナビ → 玄関 → 一覧（表示切替含む）→ 詳細 → フォーム → タグ管理 → サインイン／設定の磨き込み。
