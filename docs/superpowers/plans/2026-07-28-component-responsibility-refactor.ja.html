コンポーネント責務分割 実装計画

実装エージェント向け: 必須サブスキル: この計画をタスク単位で実装するには、superpowers:subagent-driven-development（推奨）または superpowers:executing-plans を使用する。進捗はチェックボックス（- [ ]）で追跡する。

目的: 現在の UI、URL、データ契約、メッセージ、実行時の挙動をすべて維持しつつ、各ファイルの主な変更理由が1つだけになるよう Pantry の本番コードを再編成する。

アーキテクチャ: route は、route 宣言、validation、loader の起動、screen の配線を担う接続層とする。ドメイン UI とユースケースは浅い feature フォルダーに配置し、shared UI は src/shared/components 配下に配置する。依存関係は route -> feature -> shared/infrastructure の方向に限定し、広範な barrel は直接 import に置き換える。TanStack Server Function は1モジュール1ユースケースに分割する一方、まとまりのある状態バリアントと密結合したフォームフィールドは同じファイルに維持する。

技術スタック: TypeScript、React 19、TanStack Start/Router/Query、Cloudflare Workers、Better Auth、Drizzle ORM、Turso、Base UI、Formisch、Valibot、Panda CSS、Vitest。

制約と不変条件

  • これは構造的なリファクタリングである。表示文言、視覚的挙動、route パス、検索パラメーターの意味、Server Function の入出力、query の順序、エラーの同一性やメッセージ、ナビゲーション状態、リクエスト順序を変更しないこと。
  • 互換性用 barrel を追加しないこと。利用側は具体的な所有モジュールを直接 import する。
  • テストやブラウザーのスモークテストを追加しないこと。既存テストは実装とともに移動し、import のみ更新する。
  • ユーザーが明示的に要求しない限り commit しないこと。
  • route loader が開始した Promise は、await せず遅延データとして渡す現在の挙動を維持すること。生成側または利用側を移動したという理由だけで Promise を await しない。
  • router.invalidate() と ErrorBoundary のリセット挙動を維持すること。
  • ナビゲーション状態キー newBookmarkCreated、bookmarkUpdated、bookmarkDeleted、newTagCreated、tagUpdated を維持すること。
  • リスト検索のデフォルト limit: 50、offset: 0、view、tagMode: 'and'、sort: 'newest' を維持すること。
  • server-only モジュールをクライアント向け barrel やコンポーネントの import に含めないこと。

export async function getRequestSession() {
